# Task 020: Vite + npm Wiring for `theme-blank-demo`

**Status**: completed
**Depends on**: 017
**Retry count**: 0

## Description
Create the JS entry points for the new package: the package extension entry (`resources/js/index.ts` — declares the package's contribution to the module registry), the Vite bundle entry (`resources/js/main.ts` — imports CSS layers, tokens, base, layouts, components, then calls `defineAllComponents()`), and the hand-maintained `extensions.ts` module-load list at `resources/js/extensions.ts` (NOT inside `.generated/` — the file is deliberately hand-maintained, so it lives at the top level of the JS resources directory). Additionally wire the new entry into the root `vite.config.ts` so it actually gets built, add a Vite alias for `@markommerce/theme-blank-demo` (matches the symmetry of the existing `@markommerce/frontend` and `@markommerce/theme-blank` aliases), and extend `components/index.ts` in `@markommerce/theme-blank` to import the 10 Phase 3 form-control modules (they currently are not imported anywhere — task 003 missed them).

## File Shapes

### `index.ts`

Unlike `frontend-demo/index.ts` (which registers `markommerce-counter` + a mixin), `theme-blank-demo` does not contribute any components of its own — every component it renders is already registered by `@markommerce/theme-blank`. The extension entry is therefore a no-op import side-effect:

```typescript
// theme-blank-demo registers no components of its own — it is purely a
// showcase page that depends on the registrations contributed by
// @markommerce/theme-blank. This file exists so the markommerceModuleScanner
// has a stable entry point to import.
export {};
```

### `main.ts`

```typescript
// Cascade-layer baseline first — must be the very first stylesheet so layer order is established.
import '@markommerce/frontend/css/layers.css';
// Open Props raw tokens — unlayered, sits in the global scope.
import 'open-props/style.css';
// Markommerce semantic tokens (inside @layer tokens, references Open Props).
import '@markommerce/theme-blank/css/tokens.css';
// Base styles reset (inside @layer base, references --mk-* tokens).
import '@markommerce/theme-blank/css/base.css';
// Page layout structures (inside @layer theme, defines grid column structures).
import '@markommerce/theme-blank/css/layouts.css';
// Theme-blank components — importing the package main entry triggers the side-effect
// `import './components';` in @markommerce/theme-blank/resources/js/index.ts, which then
// pulls in every mk-* component file. NOTE: that file is updated in this task to import
// the 10 form-control modules in addition to the 12 primitives it already covers.
import '@markommerce/theme-blank';
// Hand-maintained module-load list. The Vite scanner plugin only writes
// to packages/frontend-demo/resources/js/.generated/extensions.ts — it does NOT regenerate
// this file. Keep the contents stable; no HMR-time updates.
import './extensions';
// Finally, compose mixins onto bases and define the elements.
import { defineAllComponents } from '@markommerce/frontend';
defineAllComponents();
```

The import path `@markommerce/theme-blank` resolves via the existing `vite.config.ts` alias (line 41-43) and the existing tsconfig `paths` entry. The new line `import '@markommerce/theme-blank';` triggers `packages/theme-blank/resources/js/index.ts` which does `import './components';` which is what task 020 extends. The new `@markommerce/theme-blank-demo` alias added in this task is consumed by `extensions.ts` below.

### `extensions.ts` (hand-maintained, NOT under `.generated/`)

```typescript
// Hand-maintained module-load list. Unlike packages/frontend-demo/resources/js/.generated/extensions.ts
// (which the vite-plugin-markommerce scanner overwrites on every dev-server start),
// THIS file is NOT regenerated by any tool. Update it by hand when a new package
// is added to the markommerce module chain. The file lives at the top of resources/js
// (not under .generated/) precisely to signal this hand-maintained status to future
// maintainers — anything inside .generated/ is owned by the scanner plugin.

import '@markommerce/frontend';
import '@markommerce/theme-blank';
import '@markommerce/theme-blank-demo';

export const LOADED_MODULES = [
  { name: '@markommerce/frontend', priority: 0 },
  { name: '@markommerce/theme-blank', priority: 100 },
  { name: '@markommerce/theme-blank-demo', priority: 1010 },
] as const;
```

No `.gitignore` is required at any level for this file — it lives outside `.generated/`, so the repo-root `.gitignore` rule (`packages/*/resources/js/.generated/`) does not touch it.
